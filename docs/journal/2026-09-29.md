# 2026-09-29

Combined design, planning, and implementation session against two cards Michael opened together: `layout-compaction` and `separate-detail-pages`. They are one move — pulling the strip into the row removes the anchor the row-expansion panel hung from, and the route is where the panel goes instead. Threshold call: single-agent with a terminus gate, no spec. Built in two stages, the route first; each has its own section below.

## Decisions whose rationale the tree does not show

- **Path route, not hash route — Michael's call, reversing my first recommendation.** The hash route's only real virtue was zero Go change. The path route won on house precedent (astrometrics is the same shape: an index and one detail at `/groups/{id}`, a hand-rolled pathname matcher, no router library), on the server being able to answer a genuine 404 where a fragment never leaves the browser, and on links surviving mail rewriters once a notifier ever carries one.
- **Shape-only fallback, not registry-validated — Michael's call.** The asset handler serves the index for any well-formed `/check/<id>` and the page reports an unknown id. Validating against the registry would make the asset handler know the configured checks, a coupling bought for one 404.
- **This is the adjudicated route addition the `listener-isolation` quality asks for.** Its boundary says a route added to either surface is a design change, not sanctioned by being small. The adjudication happened in conversation and is recorded in the seam census.
- **`internal/server` restates the check-id pattern rather than importing `internal/config`.** Only `cmd` imports `config` today, and one regex was not a reason to change that. The cost is the three-place coupling below.
- **The default preset still reuses the strip's document, though its old reason is gone.** The law was written as "the same cut as the row beneath it", and there is no longer a row beneath it. The reuse stays because it is one fewer document and the check's page agrees with the estate row the reader just left.

## Couplings that span files

- **The check-id shape is stated three times:** `checkIDPattern` in `internal/config/config.go` (the origin), `checkRoute` in `internal/server/assets.go`, and `checkPath` in `ui/src/route.ts`. Each carries a comment naming the others. The failure if they drift is quiet: a configured check whose page 404s on reload, or routes on the page to a path the daemon refuses. The Go and vitest near-miss tables are the same list on purpose.
- **`navigate()` dispatches `popstate` synchronously, and `App`'s one listener depends on it.** The listener writes `openRef` before it sets route state, so every route change — the page's links and the back button alike — moves what the poll loop reads in one place. Replacing the synchronous dispatch with a state setter, or moving the ref write into an effect, reopens the shape of the 08-19 `presetRef` bug.

## Deliberate non-actions

- **The preset is not in the URL.** Every window is now-anchored, so a preset in a link names a span and never an incident; and a preset arriving by navigation would have to satisfy the landing rule's synchronous-readability requirement on a second path. It stays a click-driven session transient, carried across checks and reset to `90d` by a fresh load.
- **No rollup banner on the check page.** Someone parked on a check's page does not see trouble elsewhere. Left for Michael's placement pass rather than decided here.
- **The v0.1.0 changelog entry still describes the panel as expanding beneath the row.** That is what v0.1.0 shipped; the `Unreleased` entry carries the change.

## Stage 2, the compaction

Stage 1 was committed (`1bb061f`) before this began. Stage 2 is CSS and markup only: no pure function, test, or Go file changes.

- **The strip column's width is a `min-width` on the link, not a `width` on the cell.** The strip's bands are absolutely placed, so the cell has no content width of its own; under auto table layout a `width` is a hint the neighbors can squeeze to nothing. The floor on the link is what holds the column.
- **The link is one line box tall (`1.55em`) with the strip centered in it.** That is what levels the band with the chip and the check's name, and it makes the whole line height the click target rather than a 0.45rem sliver.
- **The check column is `nowrap`, and that is what makes the rows compact — not the padding trim.** Without it auto layout starves the check column in favor of the detail column, names and ids wrap, and rows come out taller than before the strip moved. The cost is that the detail column is the one that gives, which is what the truncation below answers.
- **The table's detail is one line, cut with an ellipsis — Michael's call at the eye pass.** A wrapped detail made a failing row several times the height of its neighbors. The full string is in the cell's `title` and on the check's page, and the line is a link there. The mechanism is `width: 100%` with `max-width: 0` on the cell: the zero is what lets a table cell be narrower than its own unwrapped content, and removing it as an apparent no-op makes a long detail widen the whole table. Two things it costs, both eased by removing the `last transition` column below and neither closed: the ellipsis keeps the head of the string, and a Go error's informative part is usually its tail (at the full measure the row reads `dial tcp 127.0.0.1:18599: connect: connection ref…`, nearly whole; at 1000 pixels of viewport it is `dial tcp 127.0.0.1:185…`); and with every other column unwrapped the table has a floor — below about 800 pixels of viewport the page scrolls sideways and the detail column is the first thing lost. There is no narrow-screen layout.
- **The table has no `last transition` column — Michael's call, in two steps: first the age came off it, then the column went.** It was never a second fact. `internal/state/store.go` rejects a record whose `last_transition` differs from `since`, so the column was the instant `in state` counts from, in a second notation. Two things the table no longer says, both still on the check's page in the bare stamp: the clock time of the change (`in state` reads `1d 23h`, and `formatDuration` drops minutes past a day), and whether the check has ever transitioned at all (`last_transition` is null until the first one; a never-transitioned check and one that changed at registration now look alike in the table). The status document still carries the field; nothing in the contract moved.
- **The check page's `last transition` keeps the stamp and drops the age — Michael's call, after asking whether the two can ever diverge. They cannot in value.** `transition()` in `internal/model/model.go` is the only writer of either field and sets both to the same instant; `NewRecord` sets `since` alone; the state store refuses to load a record where they differ. The one difference is presence: a check that has never transitioned — freshly registered, or re-baselined by a kind change — has a `since` and a null `last_transition`, so `in state` counts from registration and the stamp is a dash. That is why the fact stays on the check's page rather than folding into `in state`: it is where the page says the clock time of the change, and whether there has been one. This is the page's single exception to "every timestamp carries its age", and the stamp takes `outsideCurrentYear` because the age was what placed a stamp from another year.
- **Deliberate non-action: `main` stays at 62rem.** Widening it would relieve the detail column further, but the measure is the house language's, and with the column gone the detail is nearly whole at that measure anyway.
- **The transition list's first grid column went from 12rem to 17.5rem.** At 12rem an age of days ("8d 16h ago") ran into the chips; it only ever fit ages of seconds and minutes. Sized for the longest stamp the list can carry: a timestamp with its year and a three-digit day count.
- **Correction to stage 1's note on a scratch estate:** restarting the scratch daemon appends a real `stop`/`start` pair each time, which shows up in the list and as a marker at the strip's right edge. Regenerate the ledger and state file before a restart if that matters for what is being judged.
- **Terminus: five rounds, all `clean`, no findings and no vetoes** — one on the compaction, and a re-run after each of Michael's placement calls (the detail truncation, the age drop, the column's removal, the check page's age) so the handed-off tree is the reviewed tree. Its coverage report lists the four markdown files as uncovered; no scry quality claims markdown as territory, so that is the rubric's shape and not a gap this stage opened.

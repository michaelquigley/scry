# 2026-08-18

Mercurius review arc for the per-check history detail view spec and work order: complete. Six rounds, thirteen findings, all taken (one with a modification — the ABA fix replaced the reviewer's abort mechanism with a pure landing condition); round 6 returned ready_to_build and its one advisory (closed-window boundary pins) was taken. The arc is closed; the artifacts are the handoff to the implementation agent for the work order's three terminus-gated stages.

Durable notes the tree alone won't give you:

- **The wire truncates every timestamp to whole seconds, and the page's comparisons are at-or-after for that reason.** Verified against the generated encoder (`ogen-go/ogen` `json.EncodeDateTime` emits `time.RFC3339`), not assumed: a transition or boot whose wire timestamp equals the document's `to` can be newer in truth, so the dirty test and the `started` restart check use `>=`/at-or-after, never strict. Restoring a strict comparison looks like tightening and silently re-breaks document freshness — the false positive costs one poll interval of the honest cap and the next poll's later bound clears it.
- **The stale boolean became one precomputed cap shared by both window functions.** `displayWindow` and `detailWindow` both take the App's single per-render cap (latest good status `generated` while stale, the right edge otherwise) and compute `vouchedThrough = min(right, to while dirty, staleCap)`. The coupling spans two pure functions and the poll loop: giving either window function its own stale input lets strip and panel disagree in exactly the state they exist not to — a panel whose document sat held for days must cap at the status testimony the page still holds, not at its days-old `to`.
- **The panel's dirty test runs on every successful poll, open or closed; only the fetch is gated on the panel being open.** A closed panel accumulates no silence. Gating the *test* on open state was the round-3 gap: a transition landing during closure left the retained document's flag clean, and the reopen rendered obsolete state extended past `to`.
- **The 90d list's ages count from the history document's own arrival instant, held in `HistoryState` and committed with the document.** The status document's `receivedAt` is not a valid pairing for it: borrowing it resets every 90d event age to zero on each quiet status poll.
- **Resolved environment issue: the pi harness's idleTimeout was killing the mercurius stdio server between turns, so `record_round_notes`/`session_status` failed `not_found` on a fresh process's empty in-memory registry while the disk record stayed intact.** Fixed on the harness side (the timeout now keeps the server alive across turns), so the full broker loop — recorded notes, `close_session`'s generated synopsis — works normally; the direct-write recovery below is retired. For the arc itself: rounds were written as needed, writing `_notes.md` directly in the broker's format (commentary heading, then one `- **disposition** (ref: X): note` line per decision), reopening the session, and re-launching the round — calibration re-reads from `mercurius.yaml` each round, so nothing was lost. One earlier round ran against pane's example config before that misconfiguration was corrected and was discarded with its session directory.
- **Deliberate non-action: the tie order for rows sharing a wire timestamp (daemon rows before check rows, then by id) is a display rule, not a chronology claim.** The contract's truncation makes the ledger's sub-second order unrecoverable, and the spec says so. "Fixing" it by reaching for sub-second data would be a contract change the arc explicitly refuses.
- **The panel's landing rule has two conditions, and the second one is what makes the first complete.** A panel response lands only if its echoed bounds carry the currently selected preset's shape *and* its echoed `to` is at or after the newest status document's `generated`. The shape check alone has an ABA hole: a response to an abandoned visit to the same preset (A→B→A) matches the shape and could clear the dirty flag a failed fetch left behind. The reviewer's proposed fix — aborting in-flight fetches on preset change — was rejected because an abort cannot cancel a response whose promise already resolved, and it couples the rule to transport; the two document comparisons are pure and testable in vitest. The same-wire-second ABA variant is deliberately unresolvable: with no poll landed between dispatches, the abandoned response is indistinguishable from a fresh one on the wire and covers exactly what a fresh fetch would return.
- **The two dirty levels are committed and dispatched together, before either history request is awaited.** Round 5's finding: the work order's "mirrors refresh" wording invited sequential awaits, which leaves the panel's flag clean during the strip's in-flight request — the panel extends obsolete state past its `to`, and its own fetch, dispatched from an obsolete status stamp, is rejected by the landing rule and flaps behind the strip. The law is one pre-request block after each successful poll: evaluate both levels against that poll's document, commit both flags, dispatch both eligible fetches, then await. The panel's *test* runs on every poll, open or closed; only the *dispatch* is gated on the panel being open on a non-90d preset.
- **The mercurius findings note at `~/Sandbox/mercurius-pi-sessions.md` was corrected mid-arc and closed out on resolution:** `collect_round` also gates on the in-memory session registry (verified in `broker.go` — `b.session()` before any disk read), so no tool has disk-backed session resolution; rounds 1–4 only looked like a disk-vs-memory split because `collect_round` ran while the process was still alive. Root cause turned out to be the pi harness's idleTimeout killing the stdio server between turns, not a broker defect — the broker-side directions in the note (rehydrate the session map from the persisted `status.json` and round directories on boot) stand as hardening, not as the fix.
- **Deliberate non-action: the row list's timestamp includes the year only when the event falls outside the viewer's current calendar year.** Always showing it would churn every row in the default 90d view for no gain; the age beside each row keeps either form truthful. The decision lives in a small pure helper beside `formatTimestamp`, so it stays in the acceptance tables.
- **The review arc closed ready_to_build, and the final state of both artifacts was re-read top to bottom after the last fix.** The cross-checks that matter: the spec's "nothing in the page's logic reads it" is scoped to the *history* document's `generated` — the row strip's display clock remains the *status* document's `generated`, the pre-existing law the arc leaves untouched, and the two are different documents; the 90d preset bypasses `detailWindow` entirely (the source rule returns the strip's own `DisplayWindow`), so the panel's right-edge law and the strip's never need to agree in one function; and stage 1's "both window functions" wording is resolved by its own "from stage 2, the panel" clause. No cross-section drift found.

The default-window identity (omitted `to` ⇒ `to` = `generated`) stays documented there, since other consumers still use it.

As written the quality would have flagged the correct stage-1/2 code. The quality's watermark line was re-pointed to `to` and the panel's clauses added to statement/why/discrimination/boundary.

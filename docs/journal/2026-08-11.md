# 2026-08-11

State history implementation opened (Claude, implementation-agent role) against `docs/future/state-history-work-order.md`. Stage 1 — `internal/history`, the ledger store — is built, green, and terminus-clean; nothing calls it yet.

Things the tree alone will not tell you:

- **A ledger line is `dd.UnbindJSON` compacted, not `dd.Unbind` plus `json.Marshal`.** `UnbindJSON` marshals with `MarshalIndent`, so its document is multi-line and unusable as a JSONL line as-is. Going through the unbound map and marshaling it myself was the obvious one-step fix and is the wrong one: terminus round `594587abb8b9` blocked it as a df-binding violation, since dd must own serialization and not just field mapping. The extra `json.Compact` pass is that finding's resolution, and reverting it to a direct `json.Marshal` re-breaks the convention.

- **`+omitempty` on `Event`'s transition scalars is load-bearing.** `Check`/`Kind`/`From`/`To` are non-pointer, so without it every `start` and `stop` line would carry `"check":"","from":""` and friends — still passing validation, since the enforceable invariant on a flat struct is that transition fields are *zero*, not absent. The tag is what keeps lifecycle lines matching the spec's own example lines.

- **The `^\d{4}\.jsonl$` segment filter guards boot, not tidiness.** Boot strict-parses every segment and dies on anything that will not bind. An interrupted `Prune` can leave a `.scry-history-*` temporary file in the directory; reading every file rather than every *segment* would turn that litter into a fatal boot the operator cannot diagnose.

- **`resolver` keeps only the first transition after each bound, and that is complete.** Rule two reads as "the earliest transition after the bound whose `prev_since` is at or before it", which invites walking further when the first one is refused. It never helps: consecutive events chain, so event N+1's `prev_since` is event N's `ts`, already past the bound. If the first candidate is refused, every later one is too.

- **Deliberate non-action: no guard for `max(lastSaved, newest)` landing after the boot instant.** Backwards clock skew across a restart would append a `stop` stamped later than the `start` that follows it. The spec and work order are silent, the arithmetic is the daemon's own recorded evidence by design, and inventing a clamp here is design work that did not converge in phase 3.

Terminus: `594587abb8b9` returned one blocking finding (above), fixed; confirmation round `d139cec2fc95` clean with zero findings. Nothing vetoed.

Stage 2 landed after stage 1 was committed: the `saved` stamp through the `Repository` seam, the `Ledger` seam and its required place in `engine.New`, persist-then-append in every transition handler, the unconditional flush, the shutdown `stop`, `HistoryView`, `history_dir`, and `scry prune`.

- **`Save(snapshot, zeroTime)` writes no `saved` key at all**, and that is the mechanism behind prune's promise rather than an oversight. `prune` re-saves the state file with whatever stamp it loaded, so a pre-stamp file must stay pre-stamp — otherwise prune would silently invent a liveness claim it has no standing to make, and the next boot would close the ledger's gap at the wrong instant. Making `Save` always stamp would look like a tidy-up and would break that.

- **`ErrInvalidHistoryWindow` exists for a consumer that does not exist yet.** The engine replies one error channel for both bad bounds and a failed ledger read; stage 3's handler has to split them into 400 and 500. The sentinel is the seam that lets it, and `TestHistoryViewRepliesWhenTheLedgerReadFails` asserts a read failure is *not* wrapped in it. Deleting it as unused would leave the handler guessing from error strings.

- **Ledger lines come out with sorted JSON keys**, not in the order the spec's example lines show — `dd` guarantees deterministic sorted-key output, so a real line reads `{"event":"start","ts":"...","v":1}`. The spec's ordering is illustrative; key order carries no meaning and is not worth "fixing".

- **Any `cmd/scry` test built on `config.NewConfig()` must override `HistoryDir` as well as `StateFile`.** The compiled defaults point at `$XDG_STATE_HOME`/`~/.local/state`, so `TestRunDaemonStopsCleanlyWithItsContext` wrote a real ledger into the developer's home until both were pinned to `t.TempDir()`. The state file alone is no longer enough.

- **`livenessFlushInterval` is not a decorative rename.** The 60-second flush persists whether or not anything is dirty, and that unconditional save is the only thing keeping the `saved` stamp a live bound on the daemon's death — which is what bounds the unwatched gap the next boot writes. Restoring the `!dirty` early return reads like an obvious optimization on a quiet estate and would silently widen every crash gap back to the last transition. The old name (`dirtyFlushInterval`) said the opposite; terminus caught it.

- **`prune` takes a check id, never a display name.** `model.Check` carries both, and the ledger and state file are keyed by id alone, so a name-shaped argument returns a cheerful `history events='0' state entries='0'` and reads as "this check had no history". The CLI's usage string, help prose, and the `history.Store.Prune` parameter all say id for that reason.

Stage 3 landed after stage 2 was committed: the `/history` route and its schemas, the status document's `started` field, and `internal/server/history.go`.

- **A nullable enum reference needs `nullable: true` beside `allOf: [$ref]`, not beside the `$ref`.** OpenAPI 3.0 ignores siblings of a bare `$ref`, so `state_at_from: {$ref: state, nullable: true}` silently generates a non-nullable `State` and the null case becomes unrepresentable. The `allOf` wrapper is what makes ogen emit `NilState`. Same trick for the description on `kind`.

- **`historyHandler` deliberately holds no clock**, though the work order's prose says it does — that sentence predates the round that moved bound defaulting into the serialized command. Everything the document needs (`generated`, `from`, `to`) is resolved against the command's single clock read; a clock in the handler would be a second reading, and the default window's right edge could then disagree with its own watermark.

- **The 500 body echoes the internal error, segment path and line included.** That is the same discipline boot failures already follow — name the file and the line — and the status listener is the operator's own LAN surface. It reads like an information leak if you assume a public audience; it is the operator's fastest path to the broken line if you do not.

- **`Store.Append*` assumes the history directory exists.** `Boot` is what creates it, and the engine always boots first, so production never notices. A test that seeds a ledger before constructing an engine has to `MkdirAll` itself.

- **Boot's "ends in a stop" test looks at the newest event of any type, not the newest lifecycle event.** A ledger holding `stop` followed by later transitions is therefore closed again, yielding two consecutive stops. That is correct — a transition after a stop is evidence the daemon was alive — but it means a seeded test fixture must leave its last watched span open if it wants a realistic ledger.

Terminus round `68296b085a8f` returned clean with zero findings on the first pass.

Stage 4 landed after stage 3 was committed: `fetchHistory`, the pure interval builder and dirty-flag helper in `ui/src/history.ts`, `StateStrip`, the App and CheckTable wiring, strip styles, and vitest as the UI's first test runner.

- **The interval builder reads the history document alone.** The status document contributes exactly two things: the display clock and the refetch trigger. That is what makes two independently captured documents unable to disagree inside one strip — reaching into `status.checks[].state` to fill a tail band would look like an obvious simplification and would reintroduce the disagreement the design spent the `state_at_to`/`since` pair to avoid.

- **Unwatched wins over blank, and the overlay order is what enforces it.** Gaps are subtracted from every state and blank band first, then added back as their own intervals; a check born inside an unwatched span therefore renders unwatched, not blank. Where the daemon cannot testify the strip claims neither a state nor nonexistence, and `claims nothing before a fresh ledger opened` is the test that pins it.

- **The right edge is `status.generated + ageOffset`, never `Date.now()`.** Both terms stay in their own clock frame — the daemon's stamp plus locally elapsed milliseconds — which is the same arithmetic the header already does. Substituting the browser clock would silently import skew into every band boundary.

- **`historyRef` exists because the poll loop's effect closes over its initial state.** The dirty decision has to read the *current* held document, so the ref is the loop's source of truth and the state is only the render copy. Dropping the ref leaves the loop deciding from first-render state forever, which reads as "the strip never refetches".

- **Terminus's canon has almost no territory over the frontend.** The stage-4 round came back clean, but its summary names only the emoji and generated-code qualities: the Go-shaped qualities did not apply to `.ts`/`.tsx` at all. The real gate here is the vitest acceptance table plus `tsc -b`; do not read that clean verdict as a review of the React. (Closed after review: `terminus-canon` gained `projects/scry/dashboard-law` — blocking, territory `ui/src/**` — encoding the document-only, clock-frame, claim-precedence, exact-geometry, dirty-flag, and zero-remote laws; later frontend rounds see the UI.)

- **Verified against a live daemon, not just tests.** A scratch estate recorded a silent `ok` -> `late` and its hardening to `failed`, served both routes, answered 400 on an inverted window, and wrote a shutdown `stop` whose timestamp matches the state file's `saved` stamp exactly. The page itself still has not been opened in a browser this session; the eye pass remains Michael's.

The `dashboard-law` quality is what actually reviewed this stage; the first round passed only because nothing in the old rubric could see the UI. Five blocking findings followed across four rounds, all taken:

- **The dirty flag is committed before the fetch, not after it.** Committing the new status document and then awaiting history rendered the held document with `dirty: false` for the length of the request, so bands extended past a watermark the page had *already decided* was obsolete. The flag now means what its name says at every instant, not only once the request settles.

- **Band geometry lives in `placeIntervals`, not in the component.** Exact proportional endpoints and the marker-instead-of-widening rule are honesty rules, not styling; inside a render branch they were untestable. `StateStrip` now only draws what the pure function returns.

- **The unwatched prefix is the mirror of `vouchedThrough`.** The two documents are fetched in sequence, so the status-derived left edge opens *before* the history document's own window until the next pulse closes the difference — the stage-4 reasoning that the history window always starts earlier was simply wrong. That prefix renders unwatched now, exactly as the span past the right-hand watermark does: the page can speak only for `[document.from, document.to]`, and both ends are enforced. It does mean a marker tick sits at the far-left edge on first paint, standing in for a few milliseconds; taken deliberately, and worth revisiting in the eye pass if it reads badly.

- **A newly registered check dirties the flag through its `since`, though today it cannot.** Registration is not a transition, so a fresh check carries no `last_transition` to notice it by. The state is unreachable now — checks enter the registry only at boot, and boot always changes `started`, which the line above already catches — but the helper no longer depends on that Go-layer invariant holding forever.

- **Response ordering re-raised a mercurius veto, and the resolution was neither the veto nor the suggestion.** Design-review round 7 rejected `r7-fetch-boot-association` as "request generations and superseded-response handling out of scale with the tool". Terminus raised the same race from a wider angle — plain out-of-order responses, no restart required — which reason (2) of that veto did not cover. Michael's call was a third path: order responses by the document's own `generated` watermark (`supersedes`), then revalidate the arriving document against the *newest* status through `nextHistoryDirty` before clearing the flag. No counters and no request bookkeeping, and the flag now decides against the current level instead of trusting the decision the dispatching poll made. It closes the in-flight-restart case the veto left open as a side effect. `supersedes` accepts an equal watermark on purpose: refusing it would leave a quiet page permanently dirty, refetching every poll.

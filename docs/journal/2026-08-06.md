Added the `sendmail` notifier (Claude, review-companion acting as implementer at Michael's direction): a third `Notifier` implementation execing the host MTA's sendmail binary — chosen over adding SMTP auth because the MTA's store-and-forward queue beats the dispatcher's bounded retries for the failure case that matters, and no credential enters scry's config. Boot-fatal binary stat in the constructor (registry error path, like NewSMTP); `exec.CommandContext` under the attempt ctx so the deadline bound is native; `-i -f <from>` plus explicit recipients; shared message format with local line endings (the MTA owns wire form). The no-exec fence is the agent protocol's network surface — a config-named local binary behind the Notifier facade doesn't touch it; the notifications doc says so explicitly. HQ deployment should prefer sendmail over the smtp block per the host's already-configured MTA.

Two implementation catches worth keeping: the stalled-binary test exposed that `exec.CommandContext` kills the process but `Wait` blocks on output pipes held by forked children (postfix's `postdrop` pattern) — `WaitDelay = 1s` is the fix, and the test proves a stalled MTA returns the attempt in ~1.1s instead of holding it 30s. Terminus round `36bd2fc5a3e4` then caught the execute-bit check accepting binaries the daemon's own user cannot run (mode 0001-class); replaced with `exec.LookPath`, which performs a real access check for the current process, plus a rejection test for an inapplicable-class execute bit. Confirmation round `8e7ad177554b` returned clean with zero findings.

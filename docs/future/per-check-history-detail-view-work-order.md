# Per-Check History Detail View — Work Order

Realizes `docs/future/per-check-history-detail-view-spec.md`: the row strip's left edge moves to the check column, the history fetch sends explicit window bounds, and a per-check detail panel — a wider strip over a chosen preset window, the window presets themselves, and the transition list with the daemon's detail strings — expands beneath a check's row. Three terminus-gated stages, each landable and reviewable on its own. All three touch the dashboard only: no daemon change, no contract change, no `make generate`.

## Ground Truth

The integration points as they stand:

- `ui/src/api/client.ts` — `fetchHistory(signal)` sends no bounds; the route's `from`/`to` parameters are already declared in `internal/api/specs/scry.yml`, so the client simply gains two optional arguments and appends them. No spec edit, no regeneration.
- `ui/src/history.ts` — `displayWindow` derives the strip's bounds and `vouchedThrough` cap from the status document plus the held history document; `buildStrip(document, entry, window)` is window-generic and already takes any `DisplayWindow`; `placeIntervals` is container-relative, so a narrower or taller container keeps every endpoint exact; `supersedes` orders by `generated` and `nextHistoryDirty` revalidates against `generated` — window-independent in shape, and this work re-points both at the document's `to`, the end of the coverage it serves; `markerThresholdPercent` is a percentage, so it scales with the container.
- `ui/src/App.tsx` — one poll loop: `poll` fetches status, then `refresh` fetches history while the strip's level-triggered flag is set, committing the flag before the request, ordering responses by `generated` through `supersedes`, and revalidating arrivals against the newest status through `nextHistoryDirty`. `historyRef`/`statusRef` are the loop's sources of truth; `receivedAt` anchors the locally elapsed term for the status document, and `displayWindow` runs per render. The strip's `HistoryState` holds the document, the boot it was fetched under, and the dirty flag — but no arrival instant, and the status's pairing is not one the list's ages may borrow: that pairing is what this work adds.
- `ui/src/components/CheckTable.tsx` — `troubleFirst` ordering; the strip row is a single `colSpan={5}` cell, which is why the strip runs edge-to-edge and reads as a separator line; the strip renders only when the history document, the window, and the check's entry all exist.
- `ui/src/components/StateStrip.tsx` — draws `placeIntervals` output and nothing else; bands and markers carry `title` text; `role="img"`.
- `ui/src/style.css` — `.strip` is 0.45rem tall on a 62rem-max page; the unwatched hatch, the state colors, and the chip language already exist; the panel's new regions need only new classes.
- `ui/src/util.ts` — `formatTimestampWithAge(value, reference, extraMs)` is the age law's renderer and takes the document reference and the locally elapsed term as parameters, so the list's rows reuse it against the panel's own document and arrival instant.
- `ui/src/history.test.ts` — vitest acceptance tables over the pure functions; `npm --prefix ui run test` runs them. The panel's new pure functions get the same treatment.
- Terminus's `dashboard-law` quality covers `ui/src/**` and encodes the strip's laws. The panel's added clauses — now-anchoring, the 90d reuse rule, per-document vouching with the shared stale cap, the two-condition landing rule, and the panel flag re-validated through closure — are added to that quality in the terminus-canon repo *before stage 2*, so the stage-2 gate judges the new surface against the rules it must obey rather than a rubric that predates it. That edit lives in terminus-canon, not in this repo; it is a precondition for stage 2, not a deliverable of it.

## Stage 1 — the strip's alignment and explicit window bounds

The row strip's left edge moves to the check column, and the history fetch sends its bounds explicitly, so the status and history documents describe the same window to the millisecond and the left-edge marker tick stops existing.

- `ui/src/api/client.ts`: `fetchHistory(signal, from?: string, to?: string)`. Both arguments are RFC3339 UTC strings (`Date.toISOString` output); absent arguments send no parameter, so the existing parameterless call still means the daemon's default window.
- `ui/src/App.tsx`: the strip's fetch sends `to` = the polled status document's `generated` and `from` = that minus `displayWindowMs`. `to` never passes the daemon's clock reading in the normal flow, because the status poll precedes the history fetch in the same loop iteration; the one path that inverts it — a backwards host-clock jump between the two reads — surfaces as a 400, the fetch fails, the dirty flag stays set, and the next poll retries. No special case is added for it.
- `ui/src/history.ts`: the coverage watermark moves from `generated` to the echoed `to`. `supersedes` orders by `to` (equal accepted); `nextHistoryDirty` treats a `last_transition` or `since` at or after the document's `to` as dirty — `>=`, not `>`, because the wire's whole-second date-time stamps make a value that reads equal on the wire possibly newer in truth — and likewise a `started` at or after the bound, beside the not-fetched-under equality it already runs; `displayWindow` caps `vouchedThrough` at `to` while the document is dirty. `generated` becomes a stamp the page never reads. The stale boolean both window functions take becomes one precomputed stale cap, computed once per render in the App: the latest good status document's `generated` while polling is failing, and none otherwise — the row strip and, from stage 2, the panel share the one cap, and when it is absent each surface vouches to its own moving right edge (the cap is a no-op).
- `ui/src/components/CheckTable.tsx`: the strip row becomes an empty cell under `state` plus a `colSpan={4}` cell. The empty cell carries the same cell padding as its siblings, so the strip's left edge lands on the check column's left edge with no CSS change and no arithmetic.
- `ui/src/style.css`: no change expected; if the eye pass wants the strip row's vertical rhythm adjusted with the new alignment, that is a presentation-only edit inside this stage.
- `ui/src/history.test.ts`: the `unwatchedSpans` prefix case (`document.from` after the display's left edge) remains a valid pure-function input and keeps its tests, but no path through the app constructs it anymore — a comment or test name says the app-side case is retired by the explicit bounds. A new case pins the re-point: a transition landing between the document's `to` and its `generated` — applied after the status read, before the history read — dirties the held document, where the old `generated` comparison would have called it current forever. Same-second twins pin the precision law: a transition and a daemon boot whose wire timestamps equal `to` both dirty the document, and the next poll's later bound lands and clears the flag.

While clean, the tail band still extends to the display's right edge exactly as it does today: the extension is vouched by the status document's current state and `since`, and the dirty flag caps the band at the document's `to` the instant a newer transition is known. Explicit bounds change where the document's window opens, not what the page may claim at its right edge; the stage's review should confirm that, not re-derive it.

Terminus gate before stage 2.

## Stage 2 — the detail panel

The panel surface, the preset windows, and the panel's fetch discipline.

- `ui/src/history.ts` gains the panel's pure functions:
  - the preset table: `1d`, `14d`, `30d`, `90d`, `180d`, `1y` as fixed millisecond spans (day = 24h, `1y` = 365 days — the same fixed-constant arithmetic as `displayWindowMs`, no calendar math), and `all` as the fixed left bound `Date.parse('2000-01-01T00:00:00Z')` with no span.
  - `detailWindow(document, preset, ageOffset, staleCap, dirty)`: the display-window law applied to the panel's own document — right edge = the document's echoed `to` plus its locally elapsed age, left edge = right minus the preset's span (or the fixed bound for `all`), and `vouchedThrough = min(right, the document's to while dirty, staleCap)` — the same cap law `displayWindow` runs, both windows taking the one cap the App computes per render. The panel's strip speaks for the span its document covers, ending at the echoed `to`, plus the tail beyond the right edge that the status document vouches: while stale, that testimony sets the cap at the latest good status document's `generated`, exactly the strip's law, so a panel whose document has sat held for days still vouches the recent window the page holds testimony for, instead of hatching it.
  - the source rule: preset `90d` renders from the strip's held document, `DisplayWindow`, and arrival instant — the panel and the row beneath it are the same cut, and the pairing travels with the document: `HistoryState` gains an arrival field, committed with the document when a fetch lands and untouched by a failed fetch, so the helper returns `{document, window, arrival}` as one unit. Any other preset returns the panel's own held document and its own arrival pairing. One pure helper returns which.
  - `eventRows(document, entry, window)`: the list's rows, newest first — the check's transition rows (timestamp, `from`/`to`, kind, `ts` minus `prev_since` as the held duration, detail) interleaved in time with the document's daemon `start`/`stop` rows, which carry no check and are rendered as their own row type. Both kinds are filtered to the panel's display window before sorting — a row whose `ts` falls outside the window is not rendered, a row exactly at either bound is — so the list slides with the strip and the two surfaces describe one span. Rows sharing a wire timestamp break ties in a fixed display order, daemon rows before check rows, check rows by id — a presentation tiebreak, not a sub-second chronology claim, and the sort is stable enough that the list cannot reshuffle between renders.
- `ui/src/App.tsx`: the panel's state — which check is open (or none), the chosen preset (default `90d`), the panel's `HistoryState` for non-`90d` windows, and that document's arrival instant — the same arrival field the strip's `HistoryState` now carries, so each held document, strip's or panel's, owns the pairing its list ages count from. The poll loop gains a `refreshDetail` beside `refresh`, mirroring it: after each successful status poll, both dirty levels — the strip's and the panel's — are evaluated against that poll's document and both flags committed synchronously, before any history request is dispatched, and both eligible fetches (the strip's always when dirty; the panel's while the panel is open on a non-`90d` preset) are dispatched before either is awaited — neither surface may extend obsolete state during the other's in-flight request, and a panel request dispatched from an obsolete status stamp would be rejected by the landing rule and flap behind the strip. The panel's dirty test runs on every successful poll whether or not the panel is open — the level is maintained through closure, so a transition or restart landing while a non-`90d` panel is closed still dirties its held document — and only the fetch is gated on the panel: while the panel is open on a non-`90d` preset and its flag is set, commit the flag, fetch the window's explicit bounds, and land the response only if it answers the window the page currently asks for — its echoed `from`/`to` shape matches the preset currently selected (the span between them equal to the preset's span, or `all`'s fixed `from`), and its echoed `to` is at or after the newest status document's `generated` (a response to an abandoned visit to the same preset — an A→B→A switch — carries an older `to` and is rejected, and the dirty flag a failed fetch for the current window left behind stands) — ignoring a mismatch of either kind without touching the held document or the dirty flag, ordering same-preset responses by `to` through `supersedes`, and revalidating the arrival through `nextHistoryDirty` against the newest status. Aborting in-flight fetches on a preset change was considered and rejected: it cannot cancel a response that has already resolved, and it couples the landing rule to transport; the two document comparisons replace what a request counter would track. Opening a panel whose flag went dirty during closure kicks the fetch at once, as does a preset change, which also resets the held panel document; a restart's `started` change and any failed fetch dirty it through the shared test. With the panel closed or on `90d`, no second fetch exists.
- `ui/src/components/DetailPanel.tsx` (new): takes the source rule's output for one check and the current display window, and draws, top to bottom, the strip (the existing `StateStrip` under a taller class), the preset buttons (the chosen one pressed), and the list scoped to that window. Rows render `formatTimestampWithAge` against the panel's document's `to` and its arrival instant, the state change as a chip pair, the kind muted, the held duration, and the detail string wrapping — a dash when absent. Row timestamps take the page's month-day-time form and add the year when the event falls outside the viewer's current calendar year — the decision is a small pure helper beside `formatTimestamp` in `util.ts`, so the choice stays in the acceptance tables, and same-year events match the row strip exactly. Daemon rows render muted, whenever they fall in the window. The empty message is pinned to the check's own transition rows: it shows whenever and only when the check has none in the window, so a daemon-only window renders its rows and the message beneath them. The panel is a dumb drawer of what the pure functions return.
- `ui/src/components/CheckTable.tsx`: the check's strip becomes the panel's toggle — a focusable button whose click opens the panel on that check, closes it when that check is already open, or moves it when another check's strip is clicked; the open panel renders in a row beneath the check, nested under the check column.
- `ui/src/style.css`: the panel's regions — the taller strip, the preset buttons in the chip's machine-type language with the chosen preset carrying the accent, and the list's rows — plus the daemon rows' muted treatment.
- `ui/src/history.test.ts` (or a sibling `detail.test.ts`): acceptance tables for the preset table, `detailWindow` (right edge from the document's echoed `to`, left edge per preset including `all`'s fixed bound, the stale and dirty caps — stale with an old clean document and a newer status document: the cap is the status's `generated`, not the document's `to`; the same case with the document dirty: the earlier `to` wins), the source rule (including that `90d` returns the strip's document and arrival pairing, not the panel's, and that a document held across several quiet status polls keeps its arrival pairing — a later status receipt resets nothing the history document's ages depend on), the preset-shape landing check (a late response to an abandoned preset is ignored, a same-preset response lands in `to` order, and the A→B→A case: with the fresh A fetch failing first, the abandoned A response whose `to` predates the newest status's `generated` is rejected and the flag stays set; the same-wire-second variant, where no poll landed between the dispatches, is indistinguishable from a fresh response on the wire and lands correctly), the panel's flag lifecycle (the test runs on every successful poll with the panel closed, and a transition or restart landing during closure is visible on reopen: open, close, a transition lands, reopen — the flag is dirty, the fetch runs, the rendered panel carries the transition; the same case with polling stale), and the loop's scheduling (with the strip's request held unresolved, the panel's flag is already committed dirty and its request dispatched before the strip's request resolves — a successful poll revealing a transition or restart never leaves one surface clean behind the other's in-flight request), and `eventRows` (interleave order, newest first, daemon rows, a daemon row and a check row sharing a wire timestamp rendering in the defined daemon-before-check order, the empty case, a daemon-only window rendering its rows plus the empty message, a row aging past the window's left edge with no refetch, a held document whose rows all fall before the window's left edge, and boundary pins: a transition row and a daemon row exactly at the window's left or right bound remain in the list), and the list's timestamp format (an event outside the current calendar year renders with the year, one in it renders without — matching the row strip).

Terminus gate before stage 3.

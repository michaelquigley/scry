# Dashboard

The dashboard is a single page built into the binary and served from the status listener's root. It answers one question without a click: is everything okay, and if not, what isn't. There is no router, no navigation, and no charts.

The page speaks the house visual language: light mode on cool paper, Source Serif 4 for language (title, check names) and Source Code Pro for machine strings (ids, states, timestamps, durations, detail), with soft state-colored chips. Both fonts are bundled through fontsource and served from the embedded assets — the page loads nothing remote. Scry's identity follows the metawoo software-products pack: an Archivo Black wordmark baked to SVG paths in scry's sky-900 accent (`#0C4A6E` — reef below, flo the water, scry the sky), and a scrying-orb favicon (accent disc, paper gleam) — a sanctioned divergence from the identity pack's letter-tile spec, because a scrying glass names the tool better than a letter. The footer pairs the wordmark with the metawoo mark and links the repository, mirroring reef and flo.

The header shows the configured `estate_name` (the browser tab title follows it), so the page names what it watches rather than the tool watching it. A rollup banner leads. With nothing wrong it reads `all clear` with the check count; otherwise it reads `N late / N failed` and takes the color of the worse state. Below it, every check appears in one table: state chip, name with its id and kind, time in the current state, last transition, and last-result detail. Absent values render as a dash. Every timestamp carries its age, and every age — including the in-state column and the header's "as of" — counts live on a one-second client-side pulse. An age is the daemon's own span (timestamp to the document's `generated` stamp) plus the locally elapsed time since that document arrived, each term in its own clock frame, so browser and daemon clocks never mix and a stale page shows its staleness growing in real time.

Trouble sorts first — failed, then late, then ok — and within a state group alphabetically by id, so the order is stable between polls and the all-green page reads as a scannable registry. The API returns registry order and the page decides how to present it.

Time in state is measured against the document's own `generated` stamp rather than the browser's clock, so the page reports the daemon's arithmetic. Timestamps are rendered in the viewer's local zone.

## The State Strip

Beneath each check's row runs a thin band strip: the classic status-page strip, rendered from exact intervals rather than sampled buckets. Its left edge is the check column's, not the table's — the strip row carries an empty cell under `state` and spans the remaining four columns — so it reads as data attached to the check rather than as a rule drawn between checks. The window is a fixed 90 days, matching the API default. Bands take the state colors from the house palette; a check's time before it existed is left as bare track, and time no daemon can testify to takes a visually distinct hatch that reads as *absence* rather than health or trouble. Where an unwatched span overlaps a not-yet-registered one, unwatched wins: a daemon that cannot testify claims neither a state nor nonexistence.

Every endpoint is exactly proportional. A short non-ok band or gap is never widened to be visible — an instrument does not round up — so anything a reader must not miss instead gets a fixed-width marker at its true position. A thirty-minute overnight failure is 0.02% of ninety days, and it stays findable without lying about how long it lasted. Every band carries its state, duration, and start on hover.

The strip renders from the history document alone. The status document contributes exactly two things: the display clock and the refetch trigger. That is what keeps two independently captured documents from disagreeing inside one strip.

The window slides with the page's one live clock, the same arithmetic the header already does: the right edge is the latest status document's `generated` plus its locally elapsed age, the left edge is 90 days before that, every interval is clipped to those bounds, and the tail band extends to the right edge. Old incidents age out the left side as the window advances, and the two clock frames never mix.

The strip inherits the page's stale honesty at both ends. It can only speak for the span its history document covers, so anything outside `[from, to]` renders unwatched. The sliver that used to open the left edge is gone: the page sends its window explicitly — `to` is the polled status document's `generated` and `from` is 90 days before it — so the document opens exactly where the display does, and as the window slides forward the left edge advances over territory the document already covers. While status polling is failing, or while the page knows its history document is behind, bands cap at the last instant it can vouch for and the remainder to the right edge takes the unwatched treatment, growing visibly with the outage. The cap is one value computed once per render and shared by every window the page draws: the latest good status document's `generated` while polling is failing, a held document's own `to` while that document is known to be behind, and the earlier of the two when both apply. While a document is clean and polling is good there is no cap at all — its tail band runs to the moving right edge, and the dirty flag is what vouches for that span, since a clear flag means the newest poll saw no transition at or after the bound and no restart. When polling recovers, that span either vanishes (a network blip; the daemon was fine all along) or a changed `started` triggers the refetch that renders the real recorded gap.

## The Detail Panel

Clicking a check's strip opens a detail panel beneath that check's row, nested under the check column so the page's two history surfaces share one left edge. The strip is the control: clicking the open check's strip again closes it, clicking another check's moves it, and one panel is open at a time. The page stays one page — no router, no dialog, and the table's trouble-first order is untouched.

The panel is per-check but its document is per-estate: a history document carries every configured check, so opening a different check's panel reuses the held document and only a window change fetches. Top to bottom it draws a wider, taller strip over the selected window, a row of window presets, and the transition list.

### The Window

The presets are spans — `1d`, `14d`, `30d`, `90d`, `180d`, `1y` — plus `all`, with `90d` the default, so a panel opened on a check matches the row strip it grew out of. Spans are fixed millisecond constants (day = 24h, `1y` = 365 days), never calendar arithmetic, so a window is the same length whatever month it opens in. `all` is the one preset with a fixed left bound, `2000-01-01T00:00:00Z`: the daemon serves whatever the ledger holds and the years before its first `start` render as honest hatch, which is the claim they make.

Every preset is now-anchored. A preset with its own document takes its right edge from that document's echoed `to` plus the time the page has held it, and its left edge is the span back from there. `90d` is the exception, and it is a reuse rather than a second rule: it renders the row strip's held document, window, and arrival instant as one unit — the same cut as the row beneath it, so the two can never disagree — which also means its right edge rides the page's one display clock. A past-centered window is not offered; the panel's strip is a zoom on the recent horizon, and the past lives in the list.

Each rendered strip speaks only for the span its own document covers, and the shared vouching cap of the row strip applies unchanged: while polling is failing both surfaces cap at the latest good status document's `generated`, which still vouches the tail, and a document known to be behind caps at its own `to`, the earlier of the two winning. A panel whose document has sat held for days therefore still vouches the recent window the page holds testimony for, rather than hatching it.

The panel rides the existing ten-second poll under its own level-triggered dirty flag — no new timer. That flag is re-evaluated on every successful poll whether or not the panel is open, so a closed panel may hold an obsolete document but never lets one age clean; only the fetch is gated, since a closed panel has nothing to render and `90d` has no second document to fetch. Opening a panel whose flag went dirty during closure kicks the fetch at once, as does a preset change, which also abandons the held document. After each successful poll both dirty levels are evaluated against that one document and both flags committed before either request is dispatched, so neither surface can extend obsolete state during the other's in-flight fetch.

Because two history documents can be in flight, a panel response is checked twice before it lands: its echoed bounds must carry the shape of the preset currently selected, and its echoed `to` must be at or after the newest status document's `generated`. The first rejects a response to an abandoned window; the second rejects a response to an abandoned visit to the same preset, which the shape check alone cannot see. Where no poll separated the two dispatches the abandoned response carries identical bounds against the same ledger — it is the fresh response, and landing it is correct. A mismatch of either kind is ignored outright, leaving the held document and the dirty flag untouched. The row strip needs no such check: its window is anchored to the status document's own stamp, so a late landing only shortens the history-vouched coverage.

With the panel closed and no non-default preset ever chosen, the page fetches exactly one history document per refetch, and a quiet estate refetches never, as it always has.

### The Transition List

Newest first — the strip already tells the chronological story left to right, and the list answers what happened around the trouble, which lives at the right edge. It is scoped to the same window the panel's strip renders, closed at both ends, and slides with it: a row that ages past the left edge leaves the list too, computed at render time rather than by a refetch. That is what keeps the two in agreement while a quiet estate refetches never — one span, two notations.

Each transition row carries the timestamp with its age, the state change as a pair of chips, the kind the check had when it fired, the duration it held the state it left (`ts` minus `prev_since`, straight off the daemon's arithmetic), and the detail string in machine type, wrapping, a dash when absent. Ages count from the history document's own arrival instant, held with the document and never reset by a status poll, so a page holding one document through many quiet polls shows ages that keep counting forward. Timestamps render in the viewer's local zone and gain the year only when the event falls outside the viewer's current calendar year — the `1y` and `all` presets put such events in the list, and `Jan 15, 03:10` is ambiguous across years, while same-year rows read exactly as the row strip's do.

The daemon's `start` and `stop` rows interleave in time with the check's, rendered muted. They are estate-scoped rather than check-scoped, and they earn their place: a gap between two of a check's events is often nobody watching, and these rows say so in the ledger's own notation. Rows sharing a wire timestamp break ties in a fixed display order — daemon rows before check rows — which is a presentation rule keeping the list identical between renders, not a claim about sub-second chronology the contract's whole-second stamps cannot recover.

The list carries no filter and no paging, deliberately: the ledger is sparse by design, and a hand-curated estate's year of transitions is dozens of rows rather than thousands — machinery for a problem this design does not have. `prev_since` is not shown as a field of its own; the list shows the duration it implies, and the strip remains the instrument for existence boundaries. The open panel and its chosen preset are session transients with no URL surface, since the page has no router to hang one on.

A check with no transitions in the window says `no transitions in this window`. The message is pinned to the check's own rows: it claims nothing about the daemon, so a window holding only estate rows renders those rows and the message beneath them. When the window has slid entirely past what the held document covers, the strip renders fully unwatched and the list shows the same message; the pair is itself the message, and no machinery is added to say more.

## Polling and Staleness

The page polls `/api/status` every 10 seconds. A failed poll never discards the last good document: the page keeps rendering the estate it last knew and adds a banner saying the data is stale. Time in state therefore freezes at the last successful poll, which is the honest reading — the page shows the last status it actually received.

History rides that same cadence under one level-triggered dirty flag, so no second timer exists and a quiet estate refetches never. Every comparison it makes is against the held document's echoed `to` — the end of the coverage that document serves — never against the `generated` stamp the daemon takes afterward. The flag is set when a status poll shows a transition at or after that bound, when a check's `since` reaches it, when the boot stamp is one the document was not fetched under or itself falls at or after the bound, and by any failed history fetch — the missing document at first load being the same flag rather than a special case. It clears only on a fetch that lands, and every successful status poll retries while it is set.

Those comparisons are at-or-after rather than strictly-newer, because the contract carries whole-second timestamps: an instant that reads equal to the bound on the wire may be newer in truth, so equality is the case that must dirty. The cost is at most one poll interval of an honest cap, which the next poll's later bound clears.

The flag is committed before the request rather than after it, so the page never paints confident state across a span it has already decided is obsolete. Because polls are not serialized, two history fetches can be in flight at once: responses are ordered by each document's own `to`, and an arriving document is revalidated against the newest status before the flag is cleared, so a response that lost the race can neither replace a newer document nor clear a flag it does not answer for. A failed fetch commits nothing: the flag was already set before the request went out, and only a document that lands and revalidates ever clears it, so a slow request's failure cannot dirty a newer document that already arrived.

## Build

The UI is Vite, React 19, and TypeScript, built into `ui/dist` and embedded through `//go:embed all:dist`. `make build` builds the frontend first so the embedded tree always exists.

`npm --prefix ui run test` runs vitest over the page's pure arithmetic: the interval builder's acceptance table, strip placement and marker selection, the display-window derivation, response ordering, and the dirty flag's lifecycle — and, for the panel, the preset table, the detail window's now-anchoring and caps, the source rule, the two-condition landing check against the bounds the request actually sends, the poll's scheduling decision, and the transition list's interleave, tie order, and bounds. Vitest is a dev dependency only, and the strip is hand-rolled markup — the embedded page still loads nothing remote. CI runs the suite beside the frontend build.

The dashboard's own client types are generated from the committed OpenAPI contract; see [Status API](status-api.md) for the generation workflow.

For frontend work, `npm --prefix ui run dev` serves the page on port 5173 and proxies `/api` to a daemon running on `127.0.0.1:8420`.

`go build -tags no_ui ./cmd/scry` produces a headless binary. Its embedded tree is empty, so the status API serves normally and every dashboard path answers 404 rather than a partially rendered page.

## Asset Routing

Only the root path and files that exist in the embedded build are served. There is deliberately no single-page fallback: with no router, an unknown path is a genuine 404 rather than an index page. That is also what keeps the status listener from answering for `/report/*`, which belongs to the ingest listener alone.
